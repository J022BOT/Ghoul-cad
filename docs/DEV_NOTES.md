# J022 Ghoul — 离线本地 AI 驱动 LibreCAD 出图系统

> **说明**：这是开发期间的原始笔记，按当时的目录结构写成（作者本机的
> `D:\Local AI\cad-agent` 之类路径）。现在的代码已统一走 `app/portable.py`，
> 不依赖任何固定盘符。原文保留不改，是因为里面记着"当时为什么这么做"和
> 踩过的每一个坑 —— 改代码前值得先扫一眼。

一套**完全本地、断网可用**的 CAD 自动化方案：用本机运行的 Ollama 大模型，把你的自然语言画图指令
直接转换成精确的几何坐标 → 生成标准 DXF 文件 → LibreCAD 负责打开、校验与二次编辑。

整套链路只走 `localhost`，**不依赖任何外网**。下载模型/安装软件这步需要联网，装好之后即可离线运行。

## 使用方法

### 方式一：直接给指令（最常用）
双击 `D:\Local AI\cad-agent\draw.bat`，或在命令行：
```bat
draw.bat "画一个边长100mm的正方形，中心在原点"
draw.bat "画一个半径40的圆，圆心在(0,0)"
draw.bat "画一个半径30的圆，中心原点；再加水平中心线(-50,0)到(50,0)" --open
```
加 `--open` 会在生成后用 LibreCAD 自动打开。

### 方式二：从文件读指令
把指令写进 `D:\CAD\instruction.txt`，然后：
```bat
draw.bat --file D:\CAD\instruction.txt
```

### 方式三：监听模式（持续待命）
```bat
draw.bat --watch D:\CAD\instruction.txt
```
改 `instruction.txt` 内容并保存，智能体会自动按新指令重新画图（适合反复迭代）。

### 方式四：识图模式（喂图给模型）
把草图/参考图（PNG/JPG）交给系统，它会识别图形并转成 DXF：
```bat
draw.bat --image D:\CAD\test_sketch.png "请按此草图绘制，边长100"
draw.bat --image D:\CAD\sketch.jpg --open
draw.bat --image D:\CAD\sketch.jpg --mode lines     # 强制经典视觉提线
```
`--image` 支持三种 `--mode`：
| 模式 | 说明 |
|------|------|
| `auto`（默认） | 先用**经典视觉（OpenCV）**提取线条/圆/矩形；未检出足够图元时自动回退视觉模型 |
| `lines` | 强制经典视觉优先（仍会在 CV 失败时回退，保证有产出） |
| `vlm` | 只用视觉大模型 `qwen2.5vl:7b` |

### 方式四·补：经典视觉提线（精度最高的识图路线）
本地 7B 视觉模型靠语义先验"猜"形状，坐标误差常达几十像素；而 `line_extractor.py`
用确定性算法（霍夫变换/轮廓检测）把草图上的线条**算**出来——直线端点到端点、圆心半径
分毫不差、结果 100% 可复现，且**不需要调用大模型，约 1 秒出图**。

管线：二值化(极性自适应) → Canny 边缘 → HoughLinesP 直线 → 共线合并(虚线/粗线双边/断裂)
→ 轴对齐吸附 → 矩形识别(轮廓+直线配对，带边/角支撑度验证) → 圆识别(分波段霍夫+支持度/
切向连续性/径向一致性验证+半径精修) → 弧线碎片剔除 → 碎片串多段线 → 归一化到毫米。

Web 界面每次识图还会返回**识别叠加图**（红=矩形、蓝=圆、绿=直线、橙=多段线），
机器识别了什么一目了然。精度基准：`test_cv.py` 用 8 张带基准真相的草图（含手抖版）
验证，图元数量/位置全部命中，半径误差 <1%。

#### 识别后勾选保留线段（Web 界面）

勾选"识别后先勾选保留线段"后（图片 + 自动/线条模式），识别不再直接出图，而是返回
**带编号的预览图 + 图元清单**：每个图元有编号（与预览图白圈标号一一对应）、类型、
尺寸与坐标描述。取消勾选不要的杂线/噪点，点"生成 DXF"即按所选图元出图；
也可"跳过勾选，全部生成"。空勾选与过期会话会被明确拒绝。

#### 左栏 AI 对话

双栏布局左栏是与本地 `qwen2.5-coder:7b` 的自由对话（完全离线），可问制图知识、
DXF 格式、几何计算，或让它帮写绘图指令（复制到右栏执行）；对话与绘图相互独立。

#### 页面装饰

- **中心背景**：JOZZBOT 线条画作为全页居中水印（低透明度，不干扰操作）；
- **右上角**：看板徽章（圆形裁切 + 轻微浮动动画，`pointer-events:none` 不挡点击）；
- 浏览器标签页图标（favicon）同为 JOZZBOT；桌面快捷方式图标也换成了它
  （深色圆角底板 + 透明角，任何壁纸可见；`fix_lnk.vbs` 自愈脚本已同步指向新图标）。

#### 图形库：五角星等参数化图形精确直出

纯文本指令里的**参数化图形**（五角星/星形、正 N 边形、矩形/正方形、圆、三角形、
菱形、十字、箭头、心形、线段）由 `shapes.py` 在服务器端用确定性几何直接生成——
**不经过大模型，毫秒级出图，零坐标误差**。

为什么单独做：7B 模型做不好三角计算。修复前实测——"画一个五角星"输出 9 顶点
乱多边形；"画一个五角星，外接圆半径50"画成了五边形。五角星需要 10 个顶点、
外半径 R 与内半径 0.382R 交替、每次 +36°，模型算不准。

- 尺寸参数全支持：`半径/直径/外接圆半径/边长/长×宽/对角线/内径/臂长`，
  也认中文数字（`半径五十`）；
- 组合图形：`画一个圆和一个五角星`、`画一个半径30的圆和一个正方形`——
  自动识别并横向排版不重叠；`半径都是40` 会广播给所有图形；
- 保护性回退：`不要画五角星`（否定语）、`把左上角的圆改成红色`（编辑指令）、
  `画一个带圆孔的方形板`（机械语义）、`画一个正多边形`（参数不足）等
  一律交给大模型，图形库不瞎猜；
- 图形库未覆盖的怪异星形/组合，提示词里也内置了顶点公式作为第二层保障。

#### 按颜色过滤线条（经典视觉路线）

工程图常见"黑色轮廓 + 红色标注/蓝色中心线"。直接在指令里说即可，**精确到像素**：

- `去掉图中的红色标记，仅留下黑色标记`
- `删掉蓝色中心线`
- `只保留红色标注`

指令经 `parse_color_filter` 解析颜色意图（HSV 色相区间 + 黑/白/灰按明度判定），
生成掩膜后只提目标颜色的线条，其他颜色一律不输出——结果里会显示
`｜只留黑 去掉红` 表明过滤已生效。支持颜色：红/橙/黄/绿/青/蓝/紫/粉/棕/黑/白/灰。

解析按**分句 + 最近动词归属**："去掉红色只留黑色"里的"黑"归属更近的"只留"，
不会被句首"去掉"误伤；兼容"把红色去掉只要黑色 / 去掉红色标注只保留黑色线条 /
去红留黑 / 除了红色都去掉"等说法。暗底图（如 LibreCAD 黑底截图）自动把"黑"
放宽为"消色且亮度偏离背景"的线条；浅灰线会放宽到消色（黑/灰）重试，
避免"黑"掩码过严把灰线误杀。

> **颜色过滤在任何模式下都保证生效**：经典视觉路线按 HSV 精确分割（上述）；
> AI 理解路线（7B 视觉模型经常无视颜色指令）则由服务器**双重兜底**——
> ① **擦图**：识图前先按颜色把图擦成只剩目标色线条再交给模型，
> 模型物理上看不到非目标颜色的线，从源头保证过滤（图中没有目标色线条时
> 直接报错，不浪费一次模型调用）；② **几何校验**：擦图未启用时，把模型输出的
> 每个图元与"全量 CV 几何 / 目标色 CV 几何"在像素空间比对，贴得上全量几何
> 但贴不上目标色几何的图元一律剔除（模型坐标对不上时保守不删）。

> ⚠️ **AI 理解模式（7B 视觉大模型）的能力边界**：颜色过滤、局部提取、投影视图
> （俯视图/左视图转换）这类复杂指令，7B 模型遵循能力有限——**请用「⚡自动」或
> 「📐线条精确」模式**（走经典视觉，上述功能全部精确支持）。AI 模式适合没有
> 明显线条特征的语义化图形。

> ⚠️ **已修复的三个“双击没反应 / 一闪而过”根因**：
> 1. **编码**：`.bat` 不能含中文——cmd 按 GBK 读、文件却是 UTF-8，中文被拆成乱码字节当成命令，
>    把 `errorlevel` 等判断都冲乱，表现为“一闪而过”。现 `.bat` 只留纯 ASCII，中文提示全放
>    `launch.py`（Python 原生 Unicode，无此问题）。
> 2. **`.lnk` 不被 Windows 认可**：手写二进制 `.lnk`（缺 IDList / 标志位与数据不符）会被 Windows
>    解析成“桌面文件夹”本身，双击无反应。现改用系统原生方式生成（`make_lnk_com.py` 调 Shell COM，
>    `fix_lnk.vbs` 用 `WScript.Shell`），100% 兼容。
> 3. **COM vtable 索引错位**：ctypes 手写 vtable 时索引整体偏移，`SetPath` 实际调到了
>    `SetIconLocation` 等方法，导致“保存成功但无目标”。已按 IShellLinkW 正确索引重写。
>
> 另：`cmd` 里 `python` 常被解析成微软商店占位程序，启动脚本已锁定 WorkBuddy 自带真实 Python
> 绝对路径（`D:\WorkBuddy\resources\vendor\python\python.exe`）。

## 支持的图元类型

模型可生成的几何图元（由 `dxf_writer.py` 实现）：
- `line`      直线段（两点）
- `polyline`  多段线（支持闭合，画矩形/多边形/齿轮等）
- `circle`    圆（圆心+半径）
- `arc`       圆弧（圆心+半径+起止角）
- `text`      文字标注

所有单位为 mm（DXF 中以毫米存储，LibreCAD 打开即毫米制）。

## 常见问题

**Q: AI 模式报 "HTTP Error 404: Not Found" / 模型找不到？**
A: Ollama 进程虽在跑，但**模型列表是空的**——`ollama app.exe`（看门狗）在 serve 挂掉
   时会自动重启一个新 serve，重启的进程不带 `OLLAMA_MODELS`，就看不到 D 盘的模型了。
   `launch.py` 现在会检测这种情况并自动修复（杀看门狗+serve → 带模型目录重启），
   双击桌面入口即可自愈。手动修复：杀掉全部 ollama 进程后运行
   `set OLLAMA_MODELS=D:\Local AI\ollama\models && ollama serve`。

**Q: 提示连不上 Ollama / 端口 11434 无响应？**
A: 服务没起来。`launch.py` 会自动以绝对路径启动
   `C:\Users\ASUS\AppData\Local\Programs\Ollama\ollama.exe serve` 并显式带上
   `OLLAMA_MODELS=D:\Local AI\ollama\models`（ollama 安装器未写 PATH，且变量丢失时
   会出现"模型列表为空"）。也可手动运行 `start-ollama.bat`。

**Q: AI 不听从指令（按颜色过滤线条不行）？**
A: 颜色过滤已由服务器强制兜底，**任何模式都生效**：指令里的颜色意图经
   `parse_color_filter` 解析（分句 + 最近动词归属）；AI 识图前会先把图按颜色
   擦净（只留目标色线条），从源头保证过滤；擦图未启用时还有一层几何校验兜底
   （模型输出与全量/目标色 CV 几何比对，非目标色图元剔除）。详见上文
   "按颜色过滤线条"。投影视图（俯视/左视）需要 3D 空间理解，本地 7B 模型
   无法可靠完成，建议在 LibreCAD 中手动投影。

**Q: 识图精度不够 / 线条识别歪了？**
A: 上传图片时选 **📐线条精确** 或 **⚡自动** 模式——走经典视觉（OpenCV）提线，
   直线/圆/矩形是算出来的而不是猜的（约 1 秒出图，叠加图可核对识别结果）。
   **🧠AI 理解** 模式（7B 视觉模型）适合复杂语义图形，但坐标是估算的，适合不追求精度的场景。

**Q: 浏览器提示 "Expecting ',' delimiter" / "无法从模型输出中解析出几何 JSON"？**
A: 这是本地模型偶尔输出不规范 JSON 导致的（已全面加固）。解析器现可兼容 15 类常见缺陷：
   ```json 围栏、前后解释文字、多个 JSON 对象粘连、缺逗号、全角标点、// 与 /* */ 注释、
   尾随逗号、Python 字面量(True/None)、字符串内裸换行、elements/shapes 别名键``` 等；
   解析失败会**带上具体错误和原指令**让模型重写（最多 3 次），最后还有"实体抢救"模式
   （把零散图元对象拼成图纸）。单个图元数据损坏也只跳过该图元，不影响整张图。
   若仍遇到，换个说法重试即可。运行 `test_robust.py` 可查看全部 32 项断言。

**Q: 生成的 DXF 在 LibreCAD 里打开是空的/不对？**
A: 极少数情况下模型 JSON 解析失败会重试。可查看 `cad_agent.py` 输出日志；
   若持续失败，换更明确的指令（给出具体尺寸与坐标）。

**Q: 想换/加模型？**
A: 联网时执行 `ollama pull <模型名>`（模型会存到 `D:\Local AI\ollama\models`）。
   更小可选 `qwen2.5-coder:3b`；更强可选 `qwen2.5-coder:14b`（需更大内存）。

**Q: 模型推理很慢？**
A: 7B 模型在 CPU 上每条指令约 10–40 秒属正常。16GB 内存足够；若想更快可装 GPU 版 Ollama。

**Q: 模型画不出五角星/画出来是乱图形？**
A: 已修复——参数化图形走 `shapes.py` 服务器图形库，确定性几何直出（10 顶点、
   外 R 与 0.382R 交替），不经过模型。支持：N 角星、正 N 边形、矩形/正方形、圆、
   三角形、菱形、十字、箭头、心形、线段及简单组合（如"画一个圆和一个五角星"）。
   说"不要画五角星"这类否定/编辑指令仍会交给模型理解，不会误画。

**Q: 识图结果不准 / 草图识别有偏差？**
A: 视觉模型对清晰、带尺寸标注的图识别更好。可在指令里补尺寸（如"这是边长100的正方形"），
   或先用 LibreCAD 打开生成的 DXF 做微调。复杂工程图建议以文本指令为主、图片为辅助。

**Q: 桌宠点不动 / 鼠标被挡住？**
A: 桌宠是逐像素透明窗口——只有角色实体像素响应鼠标，透明区域点击直接穿透到桌面，
   不会挡住任何其他窗口。若整个角色都点不动，检查是否被其他全屏应用（游戏/视频）
   的独占模式遮挡。

**Q: 桌宠的 AI 回答是英文/不听话？**
A: 桌宠对话走 `qwen2.5-coder:7b` + 固定人设提示词（`desktop_pet.py` 的 `PERSONA`）。
   回答风格可在 `PERSONA` 里调整；想换模型设环境变量 `PET_MODEL`（如
   `set PET_MODEL=qwen2.5vl:7b`）后重启桌宠。离线时单击会收到明确错误提示。

## 实现原理（简述）

1. 你的指令 → `cad_agent.py` 通过 `http://localhost:11434/api/generate` 发给本地 qwen2.5-coder。
2. 模型按要求返回结构化几何 JSON（含图元类型、坐标、尺寸）。
3. `dxf_writer.py` 把 JSON 写成标准 R2000 DXF（含正确子类标记/句柄，AutoCAD/LibreCAD 均兼容）。
4. DXF 存到 `D:\CAD\`，如需 `--open` 则调 `LibreCAD.exe <文件>` 打开。

> 说明：自动化"画图"的本质是模型精确计算每个图元的坐标并写出开放格式 DXF，
> LibreCAD 作为渲染与编辑终端。这是最稳健、且真正离线可用的方案。
